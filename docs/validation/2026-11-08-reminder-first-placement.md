# 倒计时首次显示与微信语音窗口就绪

日期：2026-11-08。针对0.3.6正式版的新增用户反馈；此前并排、置顶和双屏常态位置已获用户确认。

## 原因和当前实现

真实遥控器语音段开始后，计时已经启动，但微信语音窗口尚未创建。旧控制器立即显示固定回退位置，再随首次锚点移动，造成明显跳位。

0.3.7的定位运行时同时发布锚点与首次显示就绪状态。先进行原有200ms定位查询，首次找到目标就允许显示；控制器先摆放到并排位置，再使窗口可见，不提前画固定位置。独立2秒截止保证未知版本、找不到目标或首个查询未返回时也能回退。超过截止才出现的目标仍继续跟随，不锁死固定位置。已经定位后短暂丢失目标立即在已确认的目标屏幕回退，不再次等待。

等待只影响HUD可见性。真实ATVV计时起点、语音触发键、音频与系统输入切换不延后，不重新给出60秒。预览立即显示且不查询微信；预览返回实际语音时重新进行首次定位。松开、禁用、换段、睡眠和退出取消首次截止与轮询，旧查询或截止不能让结束的提示闪回。不新增设置字段、权限或依赖。

## 必要检查

- 核心106项、macOS适配器114项通过。新增覆盖首次缺失不允许显示、延迟目标就绪、2秒截止且首个查询仍未返回、截止后仍能跟随、短按松开/重按/退出取消旧截止与旧查询、就绪通知内取消不会复活轮询。
- 独立CLT Release和bundle自检通过；隔离预览使用独立应用标识和配置域，不覆盖Applications应用或访问实际按键/音频。
- 原生检查验证：初次250ms无面板，延迟目标到达后首个可见位置就是目标位置，后续文字向上扩展/移动保持原行为；预览立即显示且不查询微信，返回实际段等待定位，缺失超过2秒后显示固定回退，退出后无新查询，窗口非激活与穿透属性、本应用焦点不变。
- 首次原生检查在新增的等待超时阶段后，仍将退出后的读取次数与该阶段之前的旧计数比较，导致断言失败；已改为退出前拍摄读取计数，保留失败日志，不为通过测试改变生产行为。

原生窗口检查与真实微信首次创建窗口的硬件时序分别报告；不能用模拟锚点通过代替真机首次出现验收。长录音、音频重连与系统权限本次未重测，相关代码未改动。原始日志和偏好备份留在被忽略的`.local/`，不提交个人路径、窗口ID、截图或输入内容。
