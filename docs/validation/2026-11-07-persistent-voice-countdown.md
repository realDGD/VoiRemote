# 全段倒计时、并排定位与尾部展开

日期：2026-11-07。本记录覆盖常驻倒计时及随后发现的微信3.0.1定位、层级与跨屏修正；交付事实见下方版本记录。

## 当前行为

启用“RC003 语音时限提醒”后，以真实ATVV START为起点，全段显示约60秒估计倒计时。短胶囊104×34pt；默认第50秒显示“松开再按”，尾部以0.24秒展开到164pt，提示文字距离尾端10pt。第55秒图标变红，较长的结束或接近时限状态使用192pt以免截字。系统减少动态效果时直接切换。

原schema6的`voiceLimitReminderStartSeconds`整数保留，UI明确改为“展开操作提示”，控制文案展开而非倒计时出现；范围仍为0–55秒，原配置与能力开关不重置。5秒无设备预览从约剩12秒开始，第2秒展开，5秒后隐藏，不读取微信窗口或启动音频。

定位从语音开始跟随至实际段结束，优先在绿色按钮右侧并排、垂直居中，空间不足尝试左侧及上下，无法识别或安全布局时回退固定位置。当前匹配微信3.0.0/3.0.1的已知紧凑窗口，绿色按钮校准为88×36pt、距透明窗口底边64pt；窗口归属和版本仍经原保守匹配。文字区域独立避让，不再把整个透明外框当绿色按钮边界。192×34pt面板预留最大状态空间，透明区域仍穿透；展开不重选边、不移动面板。

估算到60秒不自动停止或续录；实际STOP、松开与失败结束仍走原音频释放和系统输入恢复流程。本改动不读取文字、剪贴板、截图或音频内容，不请求新权限。

## 微信3.0.1定位修正

0.3.5升级后，用户报告提醒在绿色胶囊左上方、被其他窗口覆盖，以及点击屏幕A后仅把鼠标悬停B时两者分屏。只读探针读取到本机微信输入法3.0.1（build680），同时观察到200×130pt与350×180pt语音窗口，以及提醒与语音分处不同屏幕；不读取标题、输入文字、截图或音频。确定根因是3.0.0单一版本门禁，使3.0.1根本没有进入定位流程，始终采用鼠标屏幕回退。提醒为普通floating层级，微信为maximumWindow-2，也直接解释置顶差异。

修正保留未知形状/歧义拒绝，补入3.0.1。按用户截图及成对窗口相对边界，将绿色按钮下边距从原先未验的24pt修正为64pt；文字向上扩展保持按钮下沿与中心不变。布局按按钮所在屏幕选择并记住回退目标，面板改为与微信语音窗口同级置顶，短胶囊的固定底部居中也不再因透明预留区而偏左。

修正的必要检查：106/106核心、110/110适配器、独立CLT Release/bundle和原生提醒smoke通过。覆盖3.0.1匹配、按钮校准、文字跨屏而绿色按钮不跨屏时的目标选择、双屏原生面板跟随与丢失后留在目标屏、预览不扫描及窗口层级。第一轮原生检查错误假定用户不会移动鼠标，使第二次预览仍需等于最初屏幕的固定点；已改为按预览开始时的实际鼠标屏幕检查，不改变生产行为来迁就测试。

真实窗口原型验证：独立诊断直接编译当前HUD控制器/视图和Core/Mac模块，只将卡片标为紫色“定位预览”；使用真实微信数字窗口源、内存时钟，不接管HID、音频或系统输入，不改生产配置。用户复现点击A桌面、鼠标移B不点击、按住语音8–10秒，明确反馈“同屏并排，位置和置顶正常”。该证据覆盖本机3.0.1的真实几何和跨屏场景，尚不等于随后安装版已做完整端到端回归。
