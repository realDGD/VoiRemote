# Agent Note: Follow WeType voice capsule during a remote session

Status: implemented

## Problem

现有浮条位置固定，微信语音胶囊会根据输入焦点及屏幕变化重定位。用户要求先测位置能否稳定读取，可行时临近60秒才寻找并跟随，找不到回退固定位置。

## Decision

`SystemWeTypeWindowSource`只读公开窗口元数据，不读输入文字、音频、截图或标题，不新增权限。初期WeType3.0.0两轮2325次采样无接口失败，并观察到紧凑窗口跨屏移动；另有同进程同层级的宽窗口，不能只按进程或层级挑选。`WeTypeCapsuleMatcher`接受3.0.0/3.0.1的已知紧凑轮廓，排除510pt宽窗口；已选窗口按ID跟随移动和向上扩展。未知版本/形状、歧义或失败均回退固定位置。第二轮用户不便隔离语音与候选栏，语义分类仍保留验收边界。

用户后续要求全段倒计时常驻并与绿色语音按钮并排。`WeTypeCapsuleFollower`从真实ATVV START起，在录音期间每次读取完成200ms后复核，不堆积；估算60秒但未STOP时仍跟随，实际停止、隐藏、键盘直接语音、预览、取消、睡眠、关闭和退出不扫描。旧段结果不能复活新段。

透明窗口比绿色按钮大，原先按整个外框摆放会离按钮太远且不齐。`WeTypeCapsuleMatcher.capsuleBounds`使用88×36pt按钮、64pt底边距和水平中心校准按钮边界。0.3.5仅允许3.0.0且使用未经叠加校准的24pt底边距，实际3.0.1会直接回退；用户反馈后读取本机版本和同一时刻的数字边界，按截图与相对边界重算并以3.0.1真实窗口原型确认。这个校准仍不是微信公开接口。Core布局按这个下部按钮优先右侧并排、再左侧，垂直居中；独立保留整个上方区域作为文字障碍。侧面空间不足时再试上下，不能安全布局时仍用固定位置。跨屏依据绿色按钮位置，成功定位后更新固定回退屏幕，不跟随鼠标移动；首次未识别时才选择鼠标屏幕作为回退。面板与已识别微信语音窗口共用`maximumWindow-2`层级，避免普通floating面板被其他窗口覆盖；保持不激活、不抢焦点及鼠标穿透。

面板始终预留192×34pt的展开空间，短胶囊只绘制104pt，末段倒计时展开到164pt，较长结束态使用192pt；展开时不重新选边或移动窗口，左侧布局从靠近绿色按钮的一端向外展开。位置订阅只移动既有面板，SwiftUI直接观察提醒运行时，只有方向改变才替换根视图，展示快照和取消代次保护保持。配置schema与能力开关不变，查询不可用不影响计时、音频、触发键或系统输入恢复。文字提交、焦点和剪贴板完全由微信管理。新检查范围见[常驻倒计时记录](../../../../docs/validation/2026-11-07-persistent-voice-countdown.md)。

0.3.7将首次显示与实际计时分开：`WeTypeCapsuleState`携带锚点和`canPresent`，初次等待有效锚点，找到后直接摆到目标位置再显示；独立2秒截止保证找不到或首个查询未返回时仍能固定回退。已显示后的短暂丢失不重新等待，预览立即显示。真实ATVV起点、触发键和音频不等此截止。回调按代次隔离，松开/禁用/换段/休眠/退出取消截止和轮询，预览返回真实段也重新完成首次定位。理由与检查见[首次显示记录](../../../../docs/validation/2026-11-08-reminder-first-placement.md)。

## Alternatives considered

- 跟随鼠标或输入框：用户实测胶囊会综合输入焦点及屏幕定位，直接推算会错误，改读胶囊实际边界。
- 空闲也扫描微信窗口：没有必要。用户要求全段显示后，仅把语音段内查询从末段扩为全段，空闲不扫描。
- 通过标题、识别文字或截图识别：超出本功能所需数据，避免读取。
- 仅AX通知：本机CG元数据在无辅助功能信任时已可读；先采用有限后台复核，不为定位额外索取权限。
- 将第一个WeType窗口当胶囊：实际至少有两类同层级窗口，因此拒绝未知轮廓和多目标。

## Consequences

初版核心布局与适配器检查覆盖保守匹配、宽候选栏排除、未知/歧义回退、跨屏和边缘布局、50秒前零查询、预览与结束不续扫、取消/重按/旧回调及订阅内取消。初版原生面板与本机探测结果见[验证记录](../../../../docs/validation/2026-10-29-wetype-capsule-follow.md)，版本0.2.12的实际交付与CI结果见[交付记录](../../../../docs/validation/2026-10-29-capsule-follow-release.md)。当前规则已改为全段定位，用户在30秒固定位置原生循环中确认文字完整、展开没有跳位；随后又以3.0.1真实微信窗口验证紫色定位原型，确认点击A后鼠标悬停B时同屏并排、位置及置顶正常；检查范围及真实微信叠加仍待验的边界见[新记录](../../../../docs/validation/2026-11-07-persistent-voice-countdown.md)。

已观察到的几何轮廓不等于微信官方稳定接口。版本或外观变化时失效回退，不能以接口可读取就保证所有窗口识别正确。真实胶囊完整语义分类、WeType重启、不同外观和完整多屏叠加仍待人工验收。坐标不可靠时保留固定提示，绝不干预目标输入法或自动重开语音。

0.3.6已沿同仓库公开HTTPS源码Cask交付至Applications；用户随后确认正式橙色提醒的同屏并排及置顶正常，并指出首次显示的跳位。0.3.7已沿相同远端源码流程升级，保留配置和自启动开启状态，来源与单app检查通过；用户在请求的点击A桌面、鼠标悬停B、按住RC003语音键的补验后明确反馈“首次就并排，不再跳位”，完成该首次显示问题的真机验收。交付检查不扩写为全部音频或全屏场景通过。来源与验证范围见[版本记录](../../../../docs/validation/2026-11-07-persistent-voice-countdown.md)和[首次显示记录](../../../../docs/validation/2026-11-08-reminder-first-placement.md)。
